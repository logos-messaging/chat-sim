Commands

An expectation for check

Section titled “An expectation for check”

installations names every installation in the report. posts is optional; when given, it names every post, in each sender’s order, with the cells that matter. A cell is sent, read, unreadable, not a member, no log or no record. On a difference, check prints one line for each:

A simulation writes its expect.json in this format.

The collector’s calls

Section titled “The collector’s calls”

Each call carries Authorization: Bearer TOKEN; a browser’s GET may carry the cookie instead. A write to a run also carries the receipt the collector answered when the run was opened, in Forks-Receipt.

CallAnswer
GET /?token=TOKENa redirect to the page, with a cookie that holds the token
GET /conversationsevery conversation, the worst first
GET /conversations/IDone conversation’s report, as report --json writes it, with each run under the collector’s id
GET /runs/ID/log?line=Nline N of a run’s log, two before and three after
POST /runs, PUT /runs/ID/log?offset=N, DELETE /runs/IDopen a run, append to it, and delete it; share uses the first two

tools/forks/README.md gives every call with its statuses.

sim

Section titled “sim”

run runs the scenario once; sweep runs it K times, one after another, and with --from N those are runs N to N+K-1 of a sweep, each with the seeds it has in a sweep from run 1; compare holds a sweep in one process to the outcomes in EXPECTED and says of each run same, better, worse, re-rolled or changed, or with --write writes the sweep’s outcomes there. matrix pairs the runs in one process under HEAD with those under --base by scenario and seed, at any depth, and writes as JSON a cell for each with its change, a cell too for each run the sweeps in --asked ask of each side, and the verdict over the cells: same, better, worse, hint (one cell worse), mixed, re-rolled, no-base, no-outcome or unbuilt; without a base, each scenario’s summary. --base-point names, in place of --base, the point.json of main’s point at the base, whose runs stand in for the base’s at the same scenario and seed; --spread names that of a point whose runs the head’s are placed among, and the matrix holds of it the summary and each run of the cells’ scenarios, of each cell whether the head’s epochs are below the lowest of the point’s, and how many re-rolled cells are. tools/sim/README.md gives its fields and what decides the verdict. RIG is --one-process PATH, the path of harness-run. The flake’s app groupv2-simulation builds the runner and adds that flag to what follows --, so it runs run and sweep, and compare and matrix run with python3. --chat-cli PATH and --image IMAGE [--engine docker|podman] run chat-cli, which is on the local-network branch. DIR must not exist.

harness-run

Section titled “harness-run”

Runs every member of one group in one process on a virtual clock, and writes OUT_DIR/group.log and OUT_DIR/result.json. It exits 0 for a run, steps that stopped included, and 2, with one line on standard error, when the plan cannot be read, the directory cannot be written, or the arguments are not those two. sim --one-process writes its plan from the scenario; crates/harness/README.md gives the plan’s format and what a run leaves.
