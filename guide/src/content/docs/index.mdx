chat-sim asks one question. Does a group of logos-chat clients stay one group when the network
delays and loses what its members send?

When it does not, the group has **forked**: its members hold two states of the group, and neither
side can read what the other sends.

chat-sim runs every member of a group in one process, on a virtual clock, through a model of a
lossy network. Each run starts from a **seed**. On Linux the same seed gives the same run every
time.

- Each logos-chat pull request runs at its head and at its merge base. A comment on it says
  whether the head forks earlier or later.
- Each push to logos-chat's `main` runs too. chat-sim's site draws `main` over time.
